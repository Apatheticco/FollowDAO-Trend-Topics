  从原始素材或主动扫描热点，自动提取结构化字段，创建 Followin 热点风向标（TrendingTopic），并支持发布。
  三种触发场景：
  (A) 用户让"扫一下热点 / 找几个话题 / 批量创建今日话题" → 调 Followin MCP（metrics/news/signal/twitter）主动扫描；
  (B) 用户给一段素材（新闻/推文/描述）让创建话题 → 直接进评分；
  (C) 用户给一个标的或一句话（"查一下 REPPO" / "Aave 现在情况"）→ 多源补全资料再评分。
  ⚠️ 调研型 vs 建题型意图闸（v2.6.5）："看看/有没有 X 话题 / X 板块怎样 / 查一下 X"=**调研型→先 present 数据+评分+去重结论，问一句再建，禁止直接 create**；"建/补一个 X / 把 X 拆成 N 条 / 上线 X"=建题型→按 (B)/(C) 走。（LESSONS v2.6.5）
  全流程：采集 → 去重 → 评分 → 字段提取 + 标题优化 → 预览 → 创建 → tag 校验 → 数据核实 → 发布。

# 跑完一轮在结尾追加：  echo "$(date +%s)000" >> $HOME/.trend-scout/last-refresh.txt

### 2. 候选处置路由（status × create_at 年龄 → 走哪条规则）

> 🔁 **轮内执行序铁律**（v2.8.5）：每轮固定四步、顺序不可倒——**①扫热点**（§1 全跑）→ **②盘 8h 池**（B0 圈出 `≤8h` 全量，status 0/2 都要）→ **③处置存量**（改/合并/撤全做完：≤6h 上线题退场复查 v2.6.8、≤6h 审核题质量复审 v2.7.7、≤6h 重复合并 v2.7.3、时段闸内改价 v2.7.8——三项复查窗统一 6h；8h 只是素材 update 承接窗）→ **④最后才补新题**。**禁止先建后盘**：补题的去重基准=处置后的池子；能 update 承接的不新建。报告顺序仍 🆕补 最前，执行顺序补题最后。AUTO 同样适用。

> 🕗 **8h 管理视野闸**（v2.7.1）：扫描只管 `create_at ≤8h`；**>8h 一律不管**（不复查/不脱锚撤/不升温/不进决策/不提），当前催化由**新话题**承接。8h 是单一管理边界。（LESSONS v2.7.1）

> - **同事件有催化版存在 → 一律撤无催化版**：`2548`（纯 −7.2%）与 `2547`（「二季度业绩不及预期」+同一 −7.2%）是同一事件两版本，留 2547 撤 2548。这是去重树"留信息超集"的特例——催化本身就是超集信息。
> - **与 v2.9.6「单名 vs 板块」的分工**：那条管**冗余**（单名被板块覆盖），本闸管**完整性**（缺诱因或缺价格）。可同时命中，撤的理由写全。

> 1. **建题前查重**（B/C 素材入口强制第一步；扫描 0a 同源）：create 前必 `list` 扫**全状态 0/1/2**（v2.9.30——status=1 初始化题也是重复源），按**最后活动时间**（created_at 或最近 update 取近者）判：**≤8h 有同标的/同事件 → `update` 老题承接**，不新建；**>8h → 不再 update，直接新建**（老题已积累 heat，追改=破坏一致性+内耗，v2.6.9）；无相关 → 新建。
> 2. **两条疑似重复 → 切面判定**（v2.9.15/v2.9.21，近期反例暂留）：
>    - **真不同切面 → 都留不合并**：标题主语=**不同实体/标的/因果层**（技术根因 vs 市场反应）**且**各自独立数据锚（不同源不同量纲）。反例：Wanchain `10730`(签名重放机理) vs `10745`(NIGHT 价格情绪)——我以"数字更硬"误合并，团队恢复。**"数字更硬"只说明质量高，不说明另一条是重复**（v2.9.15）。
>    - **同事件属性侧写 → 去重留信息超集**：主语相同 + **锚重叠（指向同一笔量）**——金额/排名/后果/衍生现象只是侧写、不算不同主语。反例：Coldcard `11110`(1.16亿+BTC回流) vs `11105`(1.14亿+史上第二大)——同一笔损失，留超集 11110 撤 11105（v2.9.21）。
>    - **⏳ 抹掉时效词重建 = 时效问题升级为误导（v2.9.25）**：同一笔回溯数据换个**不带"上周/上月"**的说法重新建题 → **锚重叠即同事件该去重，且优先撤"抹掉时效词"的那条**（它读起来像刚发生、比原题更误导）。反例：`11102`「Bitmine **上周**增持 10,399 ETH，持仓 579 万」vs `11111`「Tom Lee 再购 10399 ETH，持仓突破 580 万」——同一笔 10399 枚（Tom Lee=Bitmine 董事长，579≈580 万四舍五入），后者去掉"上周"，两条同撤（本例双闸皆不过，见 §3 0b.0②）。
>    - **拿不准 → 都留**（合并的下行=误撤，保留的下行只是冗余）。
> 3. **合并动作权限**（v2.7.3/v2.9.6）：`≤6h` + 标题互异可定位 → **主动合并**（留最全 1 条，其余 `status=3`；无最全则我方新建打包）；`>6h`「单名 vs 板块全景」冗余 → 主动隐单名留板块（唯一 >6h 可动型）；**同标题刷屏 ≥3 条 → 工具清不掉**（update 命中多条报错无 ID 入口），标「系统重复 N 条」交 dev；其余 >6h → 只列不动。碎片检测**不因 >8h 豁免**（卫生问题非追新脱锚）。

### 3. 评分 → 三件套 → 建/核/发

- **⏳ 0b.0 时效双闸（v2.9.25 — 原只有①，②是 2026-08-04 用户「这种新闻你注意点时效，时效太差就去掉」补的真空白）**：两闸独立，**任一不过即砍，不进评分**。
  - **① 发布时效**：`published_ts` 超窗（首扫>24h / 刷新>4h）→ 砍。
  - **② 内容时效（新）**：**判「这条催化描述的动作发生在什么时候」，超出扫描窗即砍——不论 published_ts 多新**。触发词：**上周／上月／过去 N 天／累计／季度／13F** 等回溯性表述。典型=**机构例行披露**（8-K 周报、持仓更新、13F）、周度月度统计——这类 published_ts 永远是今天（必过①闸），但动作早被市场消化，今日不构成可交易催化。
  - **⚠️ 必须独立成闸、不能靠 A 闸兜**：这类**常常有标的**（MSTR/BMNR 股票、ETH），A≤1 拦不住。
  - **例外**：回溯数据构成**新转折**（首次转为净卖出／创纪录／趋势反转）**且**当前有价格反应 → 可留，但标题必须锚**转折本身**而非流水。**日更数据序列同此口径（v2.9.38 固化实践）**：ETF 资金流/交易所储备/持仓量等每天都有数，**只在转折或纪录时立项**（终结 N 日连续、最大单日、自 X 以来首次——11238→11315 反转即范式），日常流水不建。
  - **反例（同批三条同型，我一条没拦）**：`11101` Strategy 披露**上周**售 1,637 BTC（团队自行撤）、`11102` Bitmine **上周**增持 10,399 ETH、`11111` 同一笔数据**抹掉"上周"**重建（见去重树第 2 步）。（LESSONS v2.9.25）
