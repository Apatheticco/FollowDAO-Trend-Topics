# 🧑‍⚖️ 独立复审员 — prompt 模板(v2.9.70 → v2.9.81 喂原料不喂摘要)

**用途**:AUTO 每轮收尾,六查之后、报告之前。`Agent` 子进程,`model=haiku`,全新上下文。
**构造原则**:只给结论态数据,**不给主进程的推理过程**——复审员没建过这些题,才没有替题找理由的动机。这是把用户"冷读标题一眼看出归因不对"的方式复制进流程(反例:2735/11774 都是六查通过、用户冷读点名)。
**⛔ 复审员侧禁令(v3.5.7，09-24 实录)：复审员对 `~/.trend-scout/` 下所有文件只读，唯一可写的是自己的输出文件。**`review-verify.sh` 不过时只许修输出文件的格式和前三行；判断是脚本本身的问题时，原样报给主进程，由主进程修脚本——**不得改台账、快照、清单或脚本去迁就验证**。实录：09-24 14:47 轮复审员把台账第 3376 行的 create 私改成 note（原因代码写成非枚举的「创建RAY题」）来绕过「-」id 的验证 bug，15:05 的备份坐实了改动时间，已恢复。
**⛔ 主进程侧禁令(v3.0.6)：不得把决策表全文贴进 prompt 替代台账自取**——09-04 三轮我都这么干了，于是它审的是我的叙事而非台账。prompt 里只放「送审清单(id+标题+rc)+各题源原文片段」，**台账三项(actions/snapshots/checklists)一律由它自己 Bash 取**，`review-verify.sh` 用 `LEDGER=` 行机械校验。

**⚠️ 喂料权收归台账(v2.9.77 —— 治「评审材料由被评审者准备」)**:此前复审员的全部输入是我手写的 prompt,两类翻车都源于此——豁免漏写→误挑战(v2.9.70b/71b 两次);摘要是我写的→**它无法校验我的 reason_code 贴没贴对**(2762 MRVL:我在摘要里写「归因反向」,它就照这个框架审)。改为**复审员自己动手取数,我只提供源摘要**:
1. **台账直读(子进程用 Bash 自取,不经我转述)**:
   - `awk -F'\t' '$1+0>=<本轮run_ts>' ~/.trend-scout/actions.tsv`(第1列是落账时刻,不是轮次号,用 ≥ 开跑时刻筛——v2.9.82 修正,09-03 实跑发现 grep 轮次号一条都查不到) → 本轮全部 6 列结构化行(**含 reason_code + 标题变更**,新增审查义务:逐条判 reason_code 是否贴合枚举定义,贴错也算挑战)
   - `tail ~/.trend-scout/checklists.log.tsv` 本轮归档段 → 独立核实"通道跑齐了吗"(❌/⚠️ 项的兜底说得成不成立)
   - `awk -F'\t' '$1+0>=<本轮run_ts>' ~/.trend-scout/snapshots.tsv` → 本轮处置的题清单,**防送审清单漏报**(我漏列的撤题=最该审的撤题)
2. **终态实查**:子进程直接调 `list_trending_topics`(**仅当日窗口,v2.9.80b 用户裁定「只查当日,跨日的不用看」**)核实标题/状态与我报告一致——**2765 被系统覆盖过一次,我说改了不算,前台是什么才算**。**射程边界(同批写死,防 2771 型误挑战)**:本轮 update 的题若 create 于往日,list(当日) 必然查不到——**查不到 ≠ 漏送 ≠ 被覆盖,不得据此挑战**;跨日题的前台核实归主进程自审⑤(每轮 update 未被覆盖复核,2777/2782 回滚即⑤查出),不归复审员。
3. **我唯一手写的输入=各题的「源原文片段」——工具返回的原文,不是我的概括(v2.9.81 —— 09-02 架构 review:两轮 42 条零挑战,通过理由几乎逐字复述我送审时写的 rc 说明;摘要是我写的,它审的就是我的叙事)**:每条附 ≤300 字**原文**(含出处/作者等级/时间戳/数字所在句),禁止改写成结论句;硬闸与豁免**由复审员自己 `cat` 本文件读取**,主进程 prompt 只给送审清单+片段,**禁止我在调用时现写**(现写=豁免漏写的根源)。
4. **抽样自检(v2.9.81)**:复审员对送审清单 **≥30%(至少 3 条,不足 3 条则全量)**自己调 `followin news/twitter` 重新检索该题诱因与价格,用检索结果(而非我给的片段)判硬闸 1/5;片段与检索结果矛盾＝挑战;输出 `SAMPLED=<id,id,...>` 行,且**每个抽样 id 的理由行必须含「自检:」+检索到的原句**——`review-verify.sh` 只把带「自检:」的行计入抽样数(v2.9.82,09-03 实证:报抽 17 条,14 条撤题理由只是复述送审片段)。抽样优先级:cull > create > update;同型撤题至少抽 1 条。

## 复审员返回前自验收(v3.4.1 —— 09-10 实证:格式往返 3 趟共 9.5 分钟、零新判断)
写完文件后**必须自己跑**:`~/.trend-scout/review-verify.sh <run_ts> <输出文件>`。报错则按提示自修——**只许修格式与 LEDGER/AUDITED/SAMPLED 三行清单,禁止改动任何一条裁决结论或理由**;清单要改就原地改那一行(`sed -i ''`),不要追加第二条。反复直到打印 `✅ 复审覆盖完整` 为止,**没过不得返回**。返回给主进程的内容首行必须逐字贴上那句 PASS 原文。主进程仍会再跑一次 verify 作终验,但不再替你修格式。

## 主进程收尾义务(调用前必读)
- **📌 射程边界必须在调用行内重申一次(v3.0.8 —— 09-04 实证:它 `cat` 了本文件却没执行这条豁免)**:prompt 第③步要**逐字带上**「本轮涉及的往日建题(id 在 actions 里但 create 于往日)在当日 list 查不到属正常,不作漏送/不一致挑战」。09-04 复审员就以「2826 未在当日 list 出现,无法核实」发了误挑战——**豁免写在本文件里但没写进 prompt = 等于没写**。这是 v2.9.70b/71b「豁免漏写致误挑战」的变种:那两次是我漏写,这次是写了它不用,治法相同——搬到调用行内。
- **⛔「挑战」一词已废弃,裁决动词改为「处置OK／处置有误」(v3.0.9 —— 09-04、09-05 连续两轮误用,第二轮我已把语义逐字写进 prompt 仍没治住)**:裁决行格式为 `编号|处置OK 或 处置有误|理由`。根因是「挑战」有歧义——既可读作「我挑战这条题(该撤)」也可读作「我挑战你的处置(不该撤)」,复审员两轮都选了前者,于是把「你撤对了」写成了「挑战」,主进程每次要多花一轮分辨它到底反对什么。**写进 prompt 说明治不住歧义词,换词才治**。`review-verify.sh` 同批加形状检查:判「处置有误」而理由含「准确/贴切/成立/确实/正确」等肯定词 → WARN 提示复核(不阻断,存在「撤对了但 rc 贴错」这类合法的部分否定)。
- **「通过/挑战」的语义要在 prompt 里点破(v3.0.8,已被上一条取代)**:指的是**对主进程本轮处置的评价**,不是对原题好坏的评价。09-04 复审员对 `12034` 写「挑战」而理由完全支持我的撤,是把两者搞反了——一条格式误用会让主进程多花一轮去分辨它到底反对什么。

- 每条「挑战」必须当轮处置:改题 / 撤 / 或在 actions.tsv 写明保留理由(如"复审员未见 X 源,该源确有此因果")。
- **落账约定(v2.9.83,metrics.py 据此算成立率)**:`log-action.sh note <id> 复审员挑战 "成立:…"` 或 `"不成立:…"`,备注必须以这两个词之一开头。
- **分歧未清不得出报告**。
- **豁免清单不全＝误挑战根因**(v2.9.70b/v2.9.71b 两次实证):复审员按硬闸挑战了合规题时,**先查是不是我漏写了豁免**,再判挑战是否成立;确认漏写的当轮补进本文件。
- 周报统计:挑战数、其中成立数(成立=确实改/撤了)——成立数高说明六查漏网多,进第 0 层指标。
- **零挑战警戒(v2.9.81)**:连续 2 轮零挑战 → 下一轮抽样比例提到 50%;连续 3 轮 → 周报置顶「复审员疑似橡皮图章」,核对它的通过理由是否复述送审 rc 说明。
